# Step 6 - Digitally Sign the Authentication Request XML

## Goal

After creating the Biometric Authentication Request XML, the next step is to **digitally sign the XML** using your organization's signing certificate.

The digital signature verifies the authenticity of the request and ensures that the XML has not been modified after it was created.

Once the XML is signed, it is ready to be sent to the Aadhaar Authentication Server.

---

## Why is Digital Signature Required?

Digital Signature provides the following security benefits:

* **Authentication** – Confirms that the request was generated by an authorized AUA/Sub-AUA.
* **Integrity** – Ensures the Authentication Request XML has not been altered.
* **Non-repudiation** – Prevents the sender from denying that they generated the request.

> **Note:** The digital signature protects the Authentication Request XML but does **not** encrypt the biometric data. Biometric data is already encrypted within the `<Data>` element.

---

## Prerequisites

Before signing the XML, ensure that:

* The Authentication Request XML has been generated successfully.
* The XML includes the encrypted PID block, encrypted session key, and HMAC.
* A valid signing certificate is available.
* The corresponding private key is accessible.
* The signing certificate has not expired.

---

## Signing Workflow

```text id="d48v2n"
Authentication Request XML
            │
            ▼
Load Signing Certificate
            │
            ▼
Load Private Key
            │
            ▼
Generate XML Digital Signature
            │
            ▼
Embed Signature into XML
            │
            ▼
Signed Authentication Request XML
```

## Authentication Request Before Signing

```xml id="j9wrm1"
<Auth>

    <Uses bio="y"/>

    <Meta .../>

    <Skey>...</Skey>

    <Data>...</Data>

    <Hmac>...</Hmac>

</Auth>
```

---

## Authentication Request After Signing

After the signing process, the XML contains a `<Signature>` element.

Example:

```xml id="t5yqv8"
<Auth>

    <Uses bio="y"/>

    <Meta .../>

    <Skey>...</Skey>

    <Data>...</Data>

    <Hmac>...</Hmac>

    <Signature xmlns="http://www.w3.org/2000/09/xmldsig#">
        ...
    </Signature>

</Auth>
```

> The contents of the `<Signature>` element are generated automatically by the XML Digital Signature library. Do not manually create or modify this element.

---

## Validation Checklist

Before proceeding, verify that:

* The Authentication Request XML is well-formed.
* The `<Signature>` element has been successfully added.
* The signing certificate is valid and trusted.
* The private key matches the signing certificate.
* No modifications have been made to the XML after signing.

---

## Common Errors

| Error                        | Possible Cause                                         |
| ---------------------------- | ------------------------------------------------------ |
| Certificate not found        | Incorrect certificate path or missing certificate file |
| Invalid certificate password | Incorrect password for the certificate                 |
| Private key unavailable      | The certificate does not contain the private key       |
| Signature generation failed  | XML Digital Signature library configuration issue      |
| Certificate expired          | The signing certificate is no longer valid             |
| Signature validation failed  | The XML was modified after it was signed               |

---

## Security Best Practices

* Store signing certificates in a secure location.
* Never hardcode certificate passwords in source code.
* Never expose or commit certificate files to version control.
* Restrict access to the private key.
* Rotate certificates before they expire.

---

## Output of this Step

At the end of this step, your application should have a **digitally signed Biometric Authentication Request XML**.

The signed XML is now ready to be transmitted to the Aadhaar Authentication Server.

The next step is:

**Step 7 – Send Authentication Request**

---

## Notes

> Do not modify the Authentication Request XML after it has been digitally signed. Even a minor change, such as updating an attribute or adding whitespace, can invalidate the signature.

> Use the appropriate signing certificate for your current environment (Sandbox or Production).

> The signing process for **Biometric Authentication** is identical to the process used for **OTP Authentication**. The primary difference lies in the contents of the PID XML, which contains biometric data instead of an OTP.
