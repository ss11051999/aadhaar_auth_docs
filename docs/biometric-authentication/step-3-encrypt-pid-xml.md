# Step 3 - Encrypt PID XML

## Goal

After generating the PID XML containing the resident's biometric data, the next step is to **encrypt the PID XML** before including it in the Aadhaar Authentication Request.

The PID XML contains highly sensitive biometric information and **must never be transmitted in plain text**.

---

## Why Encrypt the PID XML?

The PID XML contains the resident's biometric data, such as:

* Fingerprint
* Iris
* Face (if supported)

To protect this sensitive information during transmission, the PID XML must be encrypted using a **new session key** generated for the current authentication request.

Encryption ensures:

* Confidentiality of the resident's biometric data.
* Protection against unauthorized access.
* Compliance with UIDAI Aadhaar Authentication specifications.

---

## Encryption Workflow

```text id="6h3szi"
PID XML
    │
    ▼
Generate Random Session Key
    │
    ▼
Encrypt PID XML using Session Key
    │
    ▼
Base64 Encode Encrypted Data
    │
    ▼
Encrypted PID Block
```

---

## Prerequisites

Before encrypting the PID XML, ensure that:

* The PID XML has been generated successfully.
* The biometric data is complete and valid.
* A new session key has been generated for this request.
* The required encryption algorithm and key size comply with the Aadhaar Authentication specifications.

---

## Input

The input to this step is the PID XML generated by the Registered Device (RD) Service.

Example:

```xml id="5c2kzw"
<Pid ts="2026-07-16T16:00:00" ver="2.0">

    <Bios>
        <Bio type="FMR">
            BASE64_ENCODED_FINGERPRINT_DATA
        </Bio>
    </Bios>

</Pid>
```

---

## Encryption Process

The encryption process consists of the following steps:

1. Generate a new random session key.
2. Encrypt the PID XML using the session key.
3. Convert the encrypted binary output into Base64 format.
4. Store the encrypted value for inclusion in the Authentication Request XML.

---

## Example Encrypted PID

```text id="3ggv2g"
Y1bX9mJ8Q0rWmPqTzV7hN4sK6fL2uE9xA5dH8pQ...
```

> The encrypted value above is only an example. Every authentication request produces a different encrypted output.

---

## Validation Checklist

Before proceeding, verify that:

* The PID XML was encrypted successfully.
* A new session key was used.
* The encrypted output is not empty.
* The encrypted PID block has been Base64 encoded (if required by your implementation).
* The original PID XML is no longer required.

---

## Security Best Practices

* Generate a **new session key** for every authentication request.
* Never reuse a session key.
* Never transmit the PID XML without encryption.
* Never log the encrypted session key or decrypted PID XML.
* Remove the plain PID XML from memory after encryption, where practical.

---

## Common Errors

| Error                           | Possible Cause                                                                  |
| ------------------------------- | ------------------------------------------------------------------------------- |
| Encryption failed               | Invalid encryption configuration or implementation issue                        |
| Empty encrypted output          | PID XML was empty or encryption failed                                          |
| Invalid session key             | Session key generation failed                                                   |
| Authentication request rejected | PID XML was not encrypted according to the Aadhaar Authentication specification |

---

## Output of this Step

At the end of this step, your application should have:

* ✅ Encrypted PID block
* ✅ Session key used for encryption

These values will be used in the next steps to generate the HMAC and construct the Authentication Request XML.

The next step is:

**Step 4 – Generate HMAC**

---

## Notes

> The encrypted PID block protects the confidentiality of the resident's biometric information during transmission.

> The encrypted output will be placed inside the `<Data>` element of the Authentication Request XML.

> Never include the original (plain) PID XML in the final Authentication Request XML.
