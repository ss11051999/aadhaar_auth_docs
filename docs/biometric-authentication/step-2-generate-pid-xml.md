# Step 2 - Generate PID XML

## Goal

After collecting the required inputs and capturing the resident's biometric data, generate the **PID (Personal Identity Data) XML**.

The PID XML is the most sensitive part of the Aadhaar Authentication Request. It contains the biometric information captured from the registered biometric device and will be encrypted before transmission.

---

## What is PID XML?

PID (Personal Identity Data) is an XML document that contains the authentication factors required for Aadhaar Authentication.

For **Biometric Authentication**, the PID XML may include:

* Fingerprint data
* Iris data
* Face data (if supported)
* Timestamp
* Device information (provided by the RD Service)

The exact structure depends on the biometric authentication type and the Registered Device (RD) Service implementation.

---

## PID XML Structure

The PID XML generated for biometric authentication is similar to the following:

```xml
<?xml version="1.0" encoding="UTF-8"?>

<Pid ts="2026-07-16T16:00:00" ver="2.0">

    <Bios>

        <Bio type="FMR" posh="UNKNOWN">
            BASE64_ENCODED_FINGERPRINT_DATA
        </Bio>

    </Bios>

</Pid>
```

> The biometric data is generated automatically by the biometric device or RD Service. You should never create or modify it manually.

---

## XML Elements

### `<Pid>`

The root element of the PID XML.

| Attribute | Description                                     |
| --------- | ----------------------------------------------- |
| `ts`      | Timestamp when the biometric data was captured. |
| `ver`     | PID XML version.                                |

---

### `<Bios>`

Container element that holds one or more biometric records.

---

### `<Bio>`

Contains the captured biometric information.

| Attribute | Description                                                                                                                    |
| --------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `type`    | Biometric type (e.g., `FMR` for Fingerprint Minutiae Record, `FIR` for Fingerprint Image Record, `IIR` for Iris Image Record). |
| `posh`    | Position or location of the captured biometric, depending on the authentication type.                                          |

The value inside the `<Bio>` element is the biometric data encoded by the RD Service.

---

## Authentication Types

The PID XML can vary depending on the authentication method.

### Fingerprint Authentication

```xml
<Pid ts="2026-07-16T16:00:00" ver="2.0">
    <Bios>
        <Bio type="FMR">
            FingerprintData
        </Bio>
    </Bios>
</Pid>
```

---

### Iris Authentication

```xml
<Pid ts="2026-07-16T16:00:00" ver="2.0">
    <Bios>
        <Bio type="IIR">
            IrisData
        </Bio>
    </Bios>
</Pid>
```

---

### Face Authentication (If Supported)

```xml
<Pid ts="2026-07-16T16:00:00" ver="2.0">
    <Bios>
        <Bio type="FID">
            FaceData
        </Bio>
    </Bios>
</Pid>
```

---

## Validation Checklist

Before proceeding to encryption, verify that:

* The PID XML is well-formed.
* The biometric data has been captured successfully.
* The `<Bio>` element contains data.
* The timestamp is correct.
* UTF-8 encoding is used.
* The PID version matches the supported API version.

---

## Security Considerations

The PID XML contains highly sensitive biometric information.

Before moving to the next step:

* Never store the PID XML in a database.
* Never write the PID XML to application logs.
* Never transmit the PID XML in plain text.
* Keep the PID XML in memory only until it is encrypted.
* Delete or clear the PID XML from memory after encryption, where practical.

## Output of this Step

At the end of this step, your application should have a valid **PID XML** containing the captured biometric data.

This PID XML will be encrypted in the next step before being included in the Aadhaar Authentication Request.

**Step 3 – Encrypt PID XML**

---

## Notes

> In most Aadhaar integrations, the **Registered Device (RD) Service** generates the PID XML automatically after a successful biometric capture. Your application typically receives the PID XML from the RD Service and uses it in the subsequent encryption and authentication steps.

> Do not alter the PID XML generated by the RD Service, as any modification may cause the authentication request to fail.
