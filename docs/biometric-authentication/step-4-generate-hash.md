# Step 4 - Generate HMAC

## Goal

After encrypting the PID XML, generate the **HMAC (Hash-based Message Authentication Code)** for the PID data.

The HMAC allows the Aadhaar Authentication Server to verify that the PID XML has not been modified before or during transmission. It provides **data integrity** for the biometric information.

---

## Why Generate an HMAC?

The HMAC ensures that the biometric data received by the server is exactly the same as the biometric data that was captured by the Registered Device (RD) Service.

It provides:

* Data integrity
* Tamper detection
* Verification that the PID XML has not been altered

> **Important:** HMAC does **not** encrypt the biometric data. Encryption is performed in the previous step.

---

## HMAC Generation Workflow

```text id="g3npvx"
PID XML
    │
    ▼
Generate SHA-256 Hash
    │
    ▼
Encrypt Hash using Session Key
    │
    ▼
Base64 Encode
    │
    ▼
HMAC Value
```

---

## Prerequisites

Before generating the HMAC, ensure that:

* The PID XML has been generated successfully.
* The PID XML has been encrypted.
* The session key used to encrypt the PID XML is available.
* The original (plain) PID XML is still available in memory for hashing.

---

## Input

The input to this step is the **plain PID XML** generated by the Registered Device (RD) Service.

Example:

```xml id="y7a0k2"
<Pid ts="2026-07-16T16:00:00" ver="2.0">

    <Bios>
        <Bio type="FMR">
            BASE64_ENCODED_FINGERPRINT_DATA
        </Bio>
    </Bios>

</Pid>
```

---

## HMAC Generation Process

Generate the HMAC using the following sequence:

1. Calculate the SHA-256 hash of the plain PID XML.
2. Encrypt the hash using the **same session key** that was used to encrypt the PID XML.
3. Base64 encode the encrypted hash.
4. Store the resulting value for inclusion in the Authentication Request XML.

---

## Example HMAC

```text id="0wl5zz"
kR8L7VvM9bNqT6wX3mH2JdP1cFsY5gAe8QxZw4Lm2Us=
```

> The value above is an example only. The HMAC generated for each authentication request will be unique.

---

## Validation Checklist

Before continuing, verify that:

* The SHA-256 hash was generated successfully.
* The correct session key was used.
* The HMAC value is not empty.
* The HMAC has been Base64 encoded (if required).
* The HMAC corresponds to the same PID XML that was encrypted in the previous step.

---

## Common Errors

| Error                  | Possible Cause                              |
| ---------------------- | ------------------------------------------- |
| Empty HMAC             | PID XML was empty or hash generation failed |
| Invalid HMAC           | Incorrect session key used                  |
| Authentication failed  | HMAC does not match the encrypted PID block |
| Hash generation failed | Invalid input data or implementation error  |

---

## Security Best Practices

* Generate the HMAC from the **original PID XML**, not from the encrypted PID block.
* Use the **same session key** used for PID encryption.
* Do not modify the PID XML after generating the HMAC.
* Avoid logging the generated HMAC in production systems.

---

## Output of this Step

At the end of this step, your application should have:

* ✅ Encrypted PID block
* ✅ Generated HMAC
* ✅ Session key (to be encrypted and included in the Authentication Request)

These components are required to build the final Aadhaar Authentication Request XML.

The next step is:

**Step 5 – Create Authentication Request XML**

---

## Notes

> The HMAC protects the integrity of the biometric PID XML, while encryption protects its confidentiality.

> Any change to the PID XML after generating the HMAC will result in an HMAC mismatch, causing the Aadhaar Authentication Server to reject the authentication request.

> Ensure that the encrypted PID block, HMAC, and session key are all generated from the same biometric authentication session.
