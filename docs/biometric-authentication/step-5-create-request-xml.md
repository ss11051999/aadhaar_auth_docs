# Step 5 - Create Authentication Request XML

## Goal

After generating the encrypted PID XML and HMAC, the next step is to create the **Aadhaar Authentication Request XML**.

This XML combines all the information required by the Aadhaar Authentication Server, including:

* Authentication details
* Authentication type
* Device metadata
* Encrypted Session Key (`Skey`)
* Encrypted PID Block (`Data`)
* HMAC (`Hmac`)

The Authentication Request XML created in this step will be digitally signed before being transmitted to the server.

---

## Prerequisites

Before creating the Authentication Request XML, ensure that you have completed the following:

* ✅ Collected all required inputs
* ✅ Captured biometric data
* ✅ Generated the PID XML
* ✅ Encrypted the PID XML
* ✅ Generated the HMAC
* ✅ Generated and encrypted the Session Key

---

## Authentication Request Structure

The Authentication Request XML contains the following major elements:

```text id="6u1rzw"
Auth
│
├── Uses
├── Meta
├── Skey
├── Data
└── Hmac
```

---

## Example Authentication Request XML

```xml id="yzw48t"
<?xml version="1.0" encoding="UTF-8"?>

<Auth
    uid="999988887777"
    ac="public"
    sa="public123"
    lk="MKQ8R2XXXXXXXXXXXXXX"
    txn="BIO202607161600001"
    ts="2026-07-16T16:00:00"
    ver="2.5">

    <Uses bio="y"/>

    <Meta
        udc="MANTRA-MFS100"
        fdc="NC"
        idc="NA"
        pip="192.168.1.10"
        lot="P"
        lov="21.2514,81.6296"/>

    <Skey ci="20260701">
        EncryptedSessionKey
    </Skey>

    <Data type="X">
        EncryptedPIDBlock
    </Data>

    <Hmac>
        GeneratedHmacValue
    </Hmac>

</Auth>
```

> The values shown above are examples. Replace them with the actual values generated by your application.

---

## XML Elements

### `<Auth>`

The root element of the Authentication Request.

| Attribute | Description                                   |
| --------- | --------------------------------------------- |
| `uid`     | Aadhaar Number or Virtual ID of the resident. |
| `ac`      | Authentication User Agency (AUA) Code.        |
| `sa`      | Sub-AUA Code.                                 |
| `lk`      | License Key issued by UIDAI.                  |
| `txn`     | Unique Transaction ID.                        |
| `ts`      | Current timestamp.                            |
| `ver`     | Aadhaar Authentication API version.           |

---

### `<Uses>`

Specifies the authentication factors being used.

For biometric authentication:

```xml id="uk2yfs"
<Uses bio="y"/>
```

Depending on the biometric modality, this may represent:

* Fingerprint Authentication
* Iris Authentication
* Face Authentication
* Multi-biometric Authentication

> If multiple authentication factors are used (for example, biometric + OTP), configure the `Uses` element according to the UIDAI Authentication API specification.

---

### `<Meta>`

Contains metadata related to the client device and request.

Typical attributes include:

| Attribute | Description             |
| --------- | ----------------------- |
| `udc`     | Device Code             |
| `fdc`     | Fingerprint Device Code |
| `idc`     | Iris Device Code        |
| `pip`     | Public IP Address       |
| `lot`     | Location Type           |
| `lov`     | Location Value          |

Depending on your RD Service implementation, additional metadata may also be included.

---

### `<Skey>`

Contains the encrypted session key.

Example:

```xml id="5qrgjo"
<Skey ci="20260701">
    EncryptedSessionKey
</Skey>
```

The `ci` attribute represents the certificate identifier used during session key encryption.

---

### `<Data>`

Contains the encrypted PID XML generated in **Step 3**.

Example:

```xml id="vuy5z0"
<Data type="X">
    EncryptedPIDBlock
</Data>
```

---

### `<Hmac>`

Contains the HMAC generated in **Step 4**.

Example:

```xml id="p5s2u6"
<Hmac>
    GeneratedHmacValue
</Hmac>
```

---

## Validation Checklist

Before proceeding, verify that:

* All mandatory attributes are present.
* The `<Uses>` element correctly represents the biometric authentication type.
* The encrypted session key has been included.
* The encrypted PID block has been included.
* The HMAC has been included.
* The Transaction ID is unique.
* The XML is well-formed.
* UTF-8 encoding is used.

---

## Common Errors

| Error              | Possible Cause                         |
| ------------------ | -------------------------------------- |
| Missing `<Skey>`   | Session key not generated or omitted   |
| Missing `<Data>`   | Encrypted PID block not included       |
| Missing `<Hmac>`   | HMAC generation failed or omitted      |
| Incorrect `<Uses>` | Wrong authentication factor configured |
| Invalid XML        | Malformed Authentication Request XML   |

---

## Output of this Step

At the end of this step, your application should have a complete **Authentication Request XML** containing:

* Authentication details
* Device metadata
* Encrypted Session Key
* Encrypted PID Block
* HMAC

The XML is **not yet ready for transmission**.

It must first be digitally signed.

The next step is:

**Step 6 – Digitally Sign Authentication Request XML**

---

## Notes

> Ensure that the values in `<Skey>`, `<Data>`, and `<Hmac>` are generated from the same biometric authentication session.

> Do not modify the Authentication Request XML after it has been digitally signed, as doing so will invalidate the digital signature.

> If your integration uses a Registered Device (RD) Service, ensure that the device metadata included in the request accurately reflects the biometric capture session.
