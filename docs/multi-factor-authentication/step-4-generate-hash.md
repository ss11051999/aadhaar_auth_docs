# Step 4 - Generate HMAC

## Goal

After encrypting the PID XML, the next step is to generate an **HMAC (Hash-based Message Authentication Code)**.

The HMAC is used to verify the integrity of the PID XML. It ensures that the authentication data has not been modified or tampered with after it was created.

For Multi-Factor Authentication, the HMAC is generated from the complete PID XML containing all selected authentication factors.

The generated HMAC is then encrypted and included in the Authentication Request XML.

---

## What is HMAC?

HMAC (Hash-based Message Authentication Code) is a cryptographic value generated from the original PID XML.

It enables the Aadhaar Authentication Server to verify that:

* The PID XML has not been modified.
* The authentication data is complete.
* The received data is identical to the data generated by the client application.

If any part of the PID XML changes after the HMAC is generated, the integrity check will fail and the authentication request will be rejected.

---

## Why is HMAC Required?

HMAC ensures the integrity of the authentication data during transmission.

It helps the Authentication Server verify that:

* OTP has not been modified.
* Biometric data has not been altered.
* Face data has not been changed.
* The complete PID XML remains intact.

This prevents unauthorized modification of the authentication request.

## HMAC Generation Process

The HMAC generation process consists of the following steps.

### 1. Read the Original PID XML

Use the complete PID XML generated in the previous step.

The PID XML may contain:

* OTP
* Fingerprint
* Iris
* Face
* Any combination of supported authentication factors

---

### 2. Generate the HMAC

Generate an HMAC from the original PID XML using the hashing algorithm specified by the Aadhaar Authentication API.

This HMAC represents the integrity of the complete authentication data.

---

### 3. Encrypt the HMAC

Encrypt the generated HMAC using the same **Session Key** that was used to encrypt the PID XML.

The encrypted HMAC is later included in the `<Hmac>` element of the Authentication Request XML.

---

## Output

After completing this step, your application should have:

* Encrypted PID XML
* Encrypted Session Key
* Encrypted HMAC

These components are required to create the Authentication Request XML.

## Validation Checklist

Before proceeding, verify that:

* The PID XML has been generated successfully.
* The HMAC has been generated successfully.
* The HMAC has been encrypted using the current Session Key.
* The same Session Key has been used to encrypt both the PID XML and the HMAC.
* The encrypted HMAC is ready to be included in the Authentication Request XML.

---

## Common Errors

| Error                       | Possible Cause                                    |
| --------------------------- | ------------------------------------------------- |
| HMAC generation failed      | Invalid hashing implementation                    |
| HMAC encryption failed      | Invalid Session Key or encryption process         |
| HMAC validation failed      | PID XML was modified after HMAC generation        |
| Invalid Session Key         | Incorrect Session Key used for encryption         |
| Data integrity check failed | Authentication data changed after HMAC generation |

---

## Best Practices

* Generate the HMAC immediately after creating the PID XML.
* Always encrypt the HMAC before adding it to the Authentication Request XML.
* Use the same Session Key for encrypting both the PID XML and the HMAC.
* Never modify the PID XML after generating the HMAC.
* Never log or store HMAC values.
* Generate a new HMAC for every authentication request.

## Next Step

Continue to **Step 5 – Create Authentication Request XML**, where the encrypted Session Key, encrypted PID XML, and encrypted HMAC are combined into a complete Authentication Request XML.

---

## Notes

> The HMAC is always generated from the **original PID XML before encryption** and is then encrypted using the same Session Key.

> The HMAC generation process is identical for **OTP**, **Biometric**, **Demographic**, **Face**, **eKYC**, and **Multi-Factor Authentication**. The only difference is the content of the PID XML.

> If the PID XML is modified after the HMAC has been generated, the Authentication Server will reject the request because the integrity verification will fail.
