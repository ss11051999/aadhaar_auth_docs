# Step 4 - Generate HMAC

## Goal

After encrypting the PID XML, the next step is to generate an **HMAC (Hash-based Message Authentication Code)**.

The HMAC is used to verify the integrity of the PID XML. It ensures that the demographic information has not been modified or tampered with after it was created.

The generated HMAC is later encrypted and included in the Authentication Request XML.

---

## What is HMAC?

HMAC (Hash-based Message Authentication Code) is a cryptographic value generated from the PID XML.

It allows the Aadhaar Authentication Server to verify that:

* The PID XML has not been altered.
* The authentication data is complete.
* The data received is exactly the same as the data generated by the client application.

If the PID XML is modified after the HMAC is generated, the HMAC verification will fail, and the authentication request will be rejected.

---

## Why is HMAC Required?

HMAC provides **data integrity** during the authentication process.

It helps ensure that:

* The demographic information remains unchanged during transmission.
* No unauthorized modifications have been made to the PID XML.
* The Authentication Server can validate the authenticity of the encrypted data.

## HMAC Generation Process

The HMAC generation process consists of the following steps:

### 1. Read the PID XML

Use the complete PID XML generated in the previous step.

---

### 2. Calculate the Hash

Generate a cryptographic hash of the PID XML using the algorithm specified by the Aadhaar Authentication API.

---

### 3. Encrypt the HMAC

Encrypt the generated HMAC using the same **Session Key** that was used to encrypt the PID XML.

The encrypted HMAC is later included in the `<Hmac>` element of the Authentication Request XML.

---

## Output

After this step, your application should have:

* Encrypted PID XML
* Encrypted Session Key
* Encrypted HMAC

These values are required to create the Authentication Request XML.

## Validation Checklist

Before proceeding, verify that:

* The PID XML has been generated successfully.
* The HMAC has been generated successfully.
* The HMAC has been encrypted using the current Session Key.
* The Session Key used for HMAC encryption is the same one used to encrypt the PID XML.
* The HMAC value is ready to be included in the Authentication Request XML.

---

## Common Errors

| Error                  | Possible Cause                               |
| ---------------------- | -------------------------------------------- |
| HMAC generation failed | Invalid hashing implementation               |
| HMAC encryption failed | Invalid Session Key or encryption process    |
| HMAC validation failed | PID XML was modified after HMAC generation   |
| Invalid Session Key    | Incorrect Session Key used during encryption |

---

## Best Practices

* Generate the HMAC immediately after creating the PID XML.
* Encrypt the HMAC before including it in the Authentication Request XML.
* Use the same Session Key for both PID XML and HMAC encryption.
* Never modify the PID XML after generating the HMAC.
* Never store or log the HMAC value.
* Generate a new HMAC for every authentication request.

---

At the end of this step, your application should have:

* Encrypted PID XML
* Encrypted Session Key
* Encrypted HMAC

These components are now ready to be included in the **Authentication Request XML**.

---

## Notes

> The HMAC is generated from the **original PID XML before encryption** and then encrypted using the same Session Key as the PID XML.

> Although the contents of the PID XML differ between OTP, Biometric, Demographic, Face, and Multi-Factor Authentication, the HMAC generation process remains the same for all authentication methods.

> If the PID XML is changed after the HMAC has been generated, the Authentication Server will reject the request because the integrity check will fail.
