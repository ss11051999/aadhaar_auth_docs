# Step 8 - Receive and Process Authentication Response

## Goal

After the Authentication Request is processed, the Aadhaar Authentication Server returns an **Authentication Response XML**.

The response indicates whether the resident has been successfully authenticated and provides additional information such as the transaction status, authentication result, and error details (if any).

---

## Response Workflow

```text
Authentication Request
        │
        ▼
Aadhaar Authentication Server
        │
        ▼
Authentication Response XML
        │
        ▼
Validate Response
        │
        ▼
Read Response Attributes
        │
        ▼
Determine Authentication Result
```

---

## Example Success Response

```xml
<?xml version="1.0" encoding="UTF-8"?>

<AuthRes
    ret="Y"
    code="100"
    txn="AUTH202607161545001"
    ts="2026-07-16T15:45:03"/>
```

> A value of `ret="Y"` indicates that the Aadhaar authentication was successful.

---

## Example Failure Response

```xml
<?xml version="1.0" encoding="UTF-8"?>

<AuthRes
    ret="N"
    err="300"
    txn="AUTH202607161545001"
    ts="2026-07-16T15:45:03"/>
```

> A value of `ret="N"` indicates that the authentication failed.

---

## Response Attributes

| Attribute | Description                                                   |
| --------- | ------------------------------------------------------------- |
| `ret`     | Authentication result (`Y` = Success, `N` = Failure).         |
| `txn`     | Transaction ID received from the request.                     |
| `ts`      | Timestamp generated by the Aadhaar Authentication Server.     |
| `code`    | Success code (if applicable).                                 |
| `err`     | Error code returned when authentication fails.                |
| `info`    | Additional information returned by the server (if available). |

> The exact attributes available may vary depending on the Aadhaar Authentication API version and your AUA/ASA integration.

---

## Processing the Response

After receiving the response:

1. Verify that the HTTP request completed successfully.
2. Parse the XML safely.
3. Confirm that the root element is `AuthRes`.
4. Match the `txn` value with the original authentication request.
5. Read the `ret` attribute.
6. If authentication failed, read the `err` attribute and handle the error appropriately.
7. Store only the information required for audit or business purposes.

---

## Success Scenario

If:

```text
ret = "Y"
```

The resident has been successfully authenticated.

Your application can now:

* Grant access to the requested service.
* Continue the business workflow.
* Record the successful authentication transaction (without storing sensitive data).

---

## Failure Scenario

If:

```text
ret = "N"
```

The authentication request was processed, but authentication was unsuccessful.

Your application should:

* Read the returned error code.
* Display an appropriate user-friendly message.
* Log the Transaction ID for troubleshooting.
* Allow the resident to retry only if appropriate.

---

## Example Error Codes

| Error Code | Description                              |
| ---------- | ---------------------------------------- |
| 300        | Invalid OTP                              |
| 330        | OTP has expired                          |
| 400        | Invalid Aadhaar Number or Virtual ID     |
| 500        | Invalid Digital Signature                |
| 569        | Authentication request validation failed |

> The error codes above are examples. Refer to the official UIDAI documentation or your AUA/ASA implementation guide for the complete and authoritative list of response codes.

---

## Validation Checklist

After processing the response, verify that:

* The Transaction ID matches the request.
* The response XML is well-formed.
* The `ret` attribute has been processed.
* Error codes have been handled correctly.
* No sensitive information has been written to application logs.

---

## Best Practices

* Always validate the response before acting on it.
* Never rely solely on the HTTP status code.
* Correlate every response with its Transaction ID.
* Display user-friendly error messages instead of raw error codes.
* Log only non-sensitive information required for monitoring and auditing.

---

## Authentication Complete

If the response indicates success (`ret="Y"`), the Aadhaar OTP Authentication process is complete.

```text
Collect Input
        │
        ▼
Generate PID XML
        │
        ▼
Encrypt PID XML
        │
        ▼
Generate HMAC
        │
        ▼
Create Authentication XML
        │
        ▼
Digitally Sign XML
        │
        ▼
Send Authentication Request
        │
        ▼
Receive Authentication Response
        │
        ▼
Authentication Successful ✅
```

---

## Notes

> A successful authentication response confirms that the resident's OTP has been verified successfully.

> Do not store the OTP, PID XML, decrypted PID data, session key, or any other sensitive authentication information after the authentication process is complete.

> Always retain only the minimum information required for auditing, reconciliation, or regulatory compliance, in accordance with UIDAI guidelines and your organization's data retention policy.
