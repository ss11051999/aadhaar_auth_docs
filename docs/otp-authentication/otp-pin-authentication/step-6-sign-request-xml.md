# Step 6 - Digitally Sign the Authentication Request XML

## Goal

After creating the Authentication Request XML, the next step is to **digitally sign the XML** using your organization's signing certificate.

The digital signature proves that the request was generated by an authorized AUA/Sub-AUA and ensures that the XML has not been modified after signing.

Only the **digitally signed Authentication Request XML** should be sent to the Aadhaar Authentication Server.

---

## Why is Digital Signature Required?

Digital Signature provides:

* **Authentication** – Verifies the identity of the sender.
* **Integrity** – Ensures that the XML has not been modified.
* **Non-repudiation** – Prevents the sender from denying that the request was generated by them.

> **Note:** Digital Signature does **not** encrypt the Authentication Request XML. Encryption is already handled for the sensitive PID data and Session Key.

---

## Prerequisites

Before signing the Authentication Request XML, ensure that:

* The Authentication Request XML has been generated successfully.
* The XML is complete and well-formed.
* A valid signing certificate is available.
* The corresponding private key is accessible.
* The certificate has not expired.

---

## Signing Workflow

```text id="gq1bvb"
Authentication Request XML
            │
            ▼
Load Signing Certificate
            │
            ▼
Load Private Key
            │
            ▼
Generate XML Digital Signature
            │
            ▼
Embed Signature into XML
            │
            ▼
Signed Authentication Request XML
```

---

## Authentication Request Before Signing

```xml
<Auth ...>

    <Uses .../>

    <Meta .../>

    <Skey>...</Skey>

    <Data>...</Data>

    <Hmac>...</Hmac>

</Auth>
```

---

## Authentication Request After Signing

Once the XML has been signed, a `<Signature>` element is added.

Example:

```xml
<Auth ...>

    <Uses .../>

    <Meta .../>

    <Skey>...</Skey>

    <Data>...</Data>

    <Hmac>...</Hmac>

    <Signature xmlns="http://www.w3.org/2000/09/xmldsig#">
        ...
    </Signature>

</Auth>
```

> The contents of the `<Signature>` element are generated automatically by the XML Digital Signature library. Do not modify or manually create this element.

---

## Validation Checklist

Before proceeding, verify that:

* The Authentication Request XML is well-formed.
* The digital signature has been successfully generated.
* The `<Signature>` element is present.
* The signing certificate is valid.
* The private key matches the signing certificate.
* No changes have been made to the XML after signing.

---

## Common Errors

| Error                        | Possible Cause                                            |
| ---------------------------- | --------------------------------------------------------- |
| Certificate not found        | Invalid certificate path or missing certificate file      |
| Invalid certificate password | Incorrect password for the P12/PFX file                   |
| Private key not found        | The certificate does not contain the required private key |
| Signature generation failed  | XML Digital Signature library configuration issue         |
| Certificate expired          | The signing certificate is no longer valid                |
| Signature validation failed  | The XML was modified after it was signed                  |

---

## Security Best Practices

* Store signing certificates in a secure location.
* Never hardcode certificate passwords in source code.
* Never commit certificate files to version control.
* Restrict access to the private key.
* Rotate certificates before they expire.

---

## Output of this Step

At the end of this step, your application should have a **digitally signed Authentication Request XML**.

This XML is now ready to be transmitted to the Aadhaar Authentication Server.

The next step is:

**Step 7 – Send Authentication Request**

---

## Notes

> Once the Authentication Request XML has been digitally signed, **do not modify any part of the XML**. Even changing a single character, adding whitespace, or modifying an attribute can invalidate the digital signature.

> Always use the appropriate signing certificate for your Sandbox or Production environment.
