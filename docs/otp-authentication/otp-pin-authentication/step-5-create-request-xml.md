# Step 5 - Create Authentication Request XML

## Goal

After generating all the required security components, the next step is to construct the **Aadhaar Authentication Request XML**.

This XML is the final request that combines:

* Authentication request details
* Encrypted Session Key (`Skey`)
* Encrypted PID Block (`Data`)
* HMAC (`Hmac`)

The XML generated in this step will be digitally signed before being sent to the Aadhaar Authentication Server.

---

## Prerequisites

Before creating the Authentication Request XML, ensure that you have completed the following steps:

* ✅ Collected all required input parameters
* ✅ Generated the PID XML
* ✅ Encrypted the PID XML
* ✅ Generated the HMAC
* ✅ Generated and encrypted the Session Key

---

## Authentication Request Structure

The Authentication Request XML consists of the following major sections:

```text id="lq6wui"
Auth
│
├── Uses
├── Meta
├── Skey
├── Data
└── Hmac
```

Each section plays an important role in the authentication process.

---

## Example Authentication Request XML

```xml id="0a9f34"
<?xml version="1.0" encoding="UTF-8"?>

<Auth
    uid="999988887777"
    ac="public"
    sa="public123"
    lk="MKQ8R2XXXXXXXXXXXXXX"
    txn="AUTH202607161545001"
    ts="2026-07-16T15:45:00"
    ver="2.5">

    <Uses otp="y"/>

    <Meta
        udc="DEVICE123"
        fdc="NC"
        idc="NA"
        pip="192.168.1.10"
        lot="P"
        lov="21.2514,81.6296"/>

    <Skey ci="20260701">
        EncryptedSessionKey
    </Skey>

    <Data type="X">
        EncryptedPIDBlock
    </Data>

    <Hmac>
        GeneratedHmacValue
    </Hmac>

</Auth>
```

> The values shown above are examples only. Replace them with the actual values generated by your application.

---

## XML Elements

### `<Auth>`

The root element of the Aadhaar Authentication Request.

| Attribute | Description                            |
| --------- | -------------------------------------- |
| `uid`     | Aadhaar Number or VID of the resident. |
| `ac`      | Authentication User Agency (AUA) Code. |
| `sa`      | Sub-AUA Code.                          |
| `lk`      | License Key issued by UIDAI.           |
| `txn`     | Unique Transaction ID.                 |
| `ts`      | Current Timestamp.                     |
| `ver`     | Authentication API Version.            |

---

### `<Uses>`

Specifies which authentication factors are being used.

For OTP Authentication:

```xml id="l69s1m"
<Uses otp="y"/>
```

This indicates that the request uses OTP for authentication.

---

### `<Meta>`

Contains information about the client device and request location.

Typical attributes include:

| Attribute | Description             |
| --------- | ----------------------- |
| `udc`     | Device Code             |
| `fdc`     | Fingerprint Device Code |
| `idc`     | Iris Device Code        |
| `pip`     | Public IP Address       |
| `lot`     | Location Type           |
| `lov`     | Location Value          |

> The required attributes depend on your implementation and UIDAI specifications.

---

### `<Skey>`

Contains the **encrypted session key**.

Example:

```xml id="ozedg5"
<Skey ci="20260701">
    EncryptedSessionKey
</Skey>
```

The `ci` attribute represents the certificate identifier used for encrypting the session key.

---

### `<Data>`

Contains the encrypted PID block generated in **Step 3**.

Example:

```xml id="itjlwm"
<Data type="X">
    EncryptedPIDBlock
</Data>
```

---

### `<Hmac>`

Contains the HMAC generated in **Step 4**.

Example:

```xml id="9tt5tx"
<Hmac>
    GeneratedHmacValue
</Hmac>
```

---

## Validation Checklist

Before proceeding, verify that:

* All mandatory attributes are present.
* The encrypted session key has been included.
* The encrypted PID block has been included.
* The HMAC has been included.
* The Transaction ID is unique.
* The XML is well-formed.
* UTF-8 encoding is used.

---

## Common Errors

| Error                    | Possible Cause                                 |
| ------------------------ | ---------------------------------------------- |
| Missing `<Skey>`         | Session key not generated or not added         |
| Missing `<Data>`         | Encrypted PID block not included               |
| Missing `<Hmac>`         | HMAC generation failed or omitted              |
| Invalid XML              | Incorrect XML structure or formatting          |
| Incorrect `Uses` element | Authentication factor not configured correctly |

---

## Output of this Step

At the end of this step, your application should have a complete **Authentication Request XML** containing:

* Authentication details
* Encrypted Session Key
* Encrypted PID Block
* HMAC

The XML is **not yet ready to be sent**.

It must first be digitally signed.

The next step is:

**Step 6 – Digitally Sign Authentication Request XML**

---

## Notes

> Do not modify the Authentication Request XML after it has been digitally signed. Any modification will invalidate the digital signature.

> Ensure that the values in `<Skey>`, `<Data>`, and `<Hmac>` are all generated from the same authentication request. Mixing values from different requests will result in authentication failure.
