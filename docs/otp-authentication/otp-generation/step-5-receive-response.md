# Step 5 - Receive and Process OTP Response

## Goal

After submitting the OTP Request, the Aadhaar Authentication Server returns an **OTP Response XML**. This response indicates whether the OTP generation request was processed successfully or if an error occurred.

In this step, you'll learn how to receive, validate, and interpret the response.

---

## Response Flow

```text
OTP Request Sent
        │
        ▼
Aadhaar Authentication Server
        │
        ▼
OTP Response XML
        │
        ▼
Validate Response
        │
        ▼
Read Response Attributes
        │
        ▼
Determine Success or Failure
```

---

## Example Success Response

> The exact response format depends on your Aadhaar Authentication Service Provider (AUA/ASA) and API version.

```xml
<?xml version="1.0" encoding="UTF-8"?>

<OtpRes
    ret="Y"
    code="100"
    txn="OTP202607161530001"
    ts="2026-07-16T15:30:02"/>
```

---

## Example Failure Response

```xml
<?xml version="1.0" encoding="UTF-8"?>

<OtpRes
    ret="N"
    err="569"
    txn="OTP202607161530001"
    ts="2026-07-16T15:30:02"/>
```

---

## Response Attributes

| Attribute | Description                                                                                           |
| --------- | ----------------------------------------------------------------------------------------------------- |
| `ret`     | Indicates whether the request was successful (`Y`) or failed (`N`).                                   |
| `txn`     | Transaction ID received from the request. Use it to correlate the response with the original request. |
| `ts`      | Timestamp generated by the server for the response.                                                   |
| `code`    | Success code (if applicable).                                                                         |
| `err`     | Error code returned when the request fails.                                                           |

> The available response attributes may vary depending on the API version and your service provider.

---

## Processing the Response

After receiving the response:

1. Ensure the HTTP status code indicates a successful transport (for example, **200 OK**).
2. Parse the XML safely.
3. Verify that the root element is `OtpRes`.
4. Read the `ret` attribute.
5. Match the `txn` value with the original request.
6. If `ret="Y"`, proceed to ask the resident to enter the received OTP.
7. If `ret="N"`, read the error code and handle the failure appropriately.

---

## Success Scenario

When:

```text
ret = "Y"
```

The OTP request has been accepted and the OTP has been generated.

The resident should receive the OTP through the configured delivery channel (SMS, Email, or both).

Your application can now proceed to the **OTP Authentication** flow.

---

## Failure Scenario

When:

```text
ret = "N"
```

The OTP generation request failed.

The application should:

* Read the error code.
* Display an appropriate error message.
* Log the Transaction ID for troubleshooting.
* Allow the user to retry if appropriate.

---

## Common Error Codes

| Error Code | Description                            |
| ---------- | -------------------------------------- |
| 569        | Invalid Aadhaar Number or Virtual ID.  |
| 570        | Invalid License Key.                   |
| 571        | Invalid Transaction ID.                |
| 572        | Invalid Timestamp.                     |
| 573        | Digital Signature verification failed. |

> Refer to the official UIDAI or your AUA/ASA documentation for the complete list of supported error codes.

---

## Best Practices

* Always correlate the response using the Transaction ID.
* Handle both success and failure responses gracefully.
* Never assume the OTP has been generated without checking the `ret` attribute.
* Avoid exposing internal error codes directly to end users.
* Log only non-sensitive information for troubleshooting.

---

## Output of this Step

At the end of this step, your application should know whether:

* The OTP was generated successfully.
* The request failed and requires corrective action.

If the OTP is generated successfully, the next process is **OTP Authentication**, where the resident enters the received OTP to complete Aadhaar authentication.

---

## Notes

> A successful OTP generation response does **not** mean the resident has been authenticated. It only confirms that the OTP has been generated and dispatched.

> Authentication is completed only after the resident submits the received OTP and it is successfully verified through the Aadhaar Authentication API.
